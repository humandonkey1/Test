# HYDRA

A general purpose lossless compressor written from scratch in C99.
No third-party code, no dependencies, no lookup dictionaries, no trained models.

```
make
./bin/hydra c -7 input output      # compress
./bin/hydra d output restored      # decompress
./bin/hydra t input                # verify round trip at every level
```

---

## What it does

One codec, three engines, chosen by level. Every stage is written here from
first principles: the range coder, the probability model, the mixer, the LZ
parser, the filters.

| Level | Engine | Use |
|-------|--------|-----|
| 1–3 | **FAST** — byte aligned LZ | GB/s decode |
| 4–6 | **STRONG** — LZ coded through the range coder | balanced |
| 7–9 | **MAX** — context mixing | best ratio |

## How it works

### Range coder

A 32-bit carry-propagating binary range coder driven by 16-bit probabilities.
Carries use the cache + pending-0xFF scheme, so a carry never has to be
propagated backwards through already-emitted output.

Measured overhead against the ideal code length: **0.113%**.

### Context mixing (levels 7–9)

Per bit, ten models predict, a gated logistic mixer combines them, and two
APM stages refine the result.

- orders 1, 2, 3, 4, 6, 8 over a two-way associative hash table
- a word model keyed on the current alphanumeric run
- a sparse model that skips bytes, for columnar layouts
- direct order-0 and order-1 tables
- a match model that predicts the continuation of the longest repeat

Contexts are re-hashed at the nibble boundary so the low four bits of a byte
get their own statistics instead of aliasing onto the high four. Each hash
slot is exactly 16 bytes, so a lookup touches one cache line.

Everything is integer-only, deliberately. The encoder and decoder must run
bit-identical model updates, and a single ULP of float drift would desync
them. `squash`/`stretch` are built at startup from a fixed-point `exp2`, and
the two tables are constructed as an exact pair — `stretch` inverts the
`squash` table that actually ships, never the ideal real-valued function.

### Filters

Reversible preprocessing, each an exact bijection:

- **delta** — subtract the value one stride back; for smooth numeric series
- **shuffle** — transpose fixed-width records column-wise; for numeric arrays
- **exe** — x86 E8/E9 relative branch targets to absolute
- **lrm** — de-duplicate repeats beyond the entropy coder's reach

### Filters are chosen by measurement, not heuristics

This turned out to matter more than any single modelling change. Every
plausible heuristic tried here was wrong on real data in at least one
direction:

- entropy of the delta residual says *apply* on smooth grayscale images.
  Measuring says it **costs 5.4%** — the context models were already
  exploiting that structure, and delta destroyed it.
- long-range de-duplication looks obviously right on a SQL dump full of
  near-identical statements. Measuring says it turns **20.6x into 17.3x** —
  the models code those repeats for less than an explicit distance pair, and
  pulling them out strips the surrounding context too.

So the encoder trial-compresses a 512 KiB slice both ways with the same
engine the block will use, and keeps the winner. The probe must use that
engine: the LZ parser sees a delta residual as noise that breaks its matches
while the context models see a tighter distribution, so asking the wrong one
gives exactly the wrong answer.

Cost is a few percent of encode time, and it is not on the decode path.

## Correctness

```
make test     # 1721 cases
make asan     # same suite under AddressSanitizer + UBSan
```

The suite is the reason to trust any number above. Every case round trips
through the public API and compares byte for byte:

- 12 content generators × 3 sizes × all 9 levels
- every size from 0 to 300 bytes, plus block-size boundaries
- sizes that are deliberately not multiples of any record width
- adversarial input: coprime cycles, graded run lengths, data that looks
  like a HYDRA frame, a compressible prefix followed by noise, a single
  flipped bit in a long run, alternating bytes
- 400 randomized fuzz iterations over mixed content and random levels
- **3000 corrupted streams** — bit flips, truncations, byte replacements —
  all rejected or benign, none silently producing wrong output

Bugs this suite caught, all of which round-tripped fine on casual input:

- **the x86 filter was not a bijection.** The set of words with top byte
  `0x00`/`0xFF` has 2²⁵ members, but sign-extending to 24 bits produces only
  2²⁴ — a two-to-one map. It failed on ~56% of dense branch data.
- **the x86 filter scan order broke symmetry.** A transform at position *q*
  rewrites bytes *q+1..q+4*, overlapping the operand window of nearby
  positions. With both sides scanning forward, the encoder judged a position
  against original bytes while the decoder judged it against already-rewritten
  ones. Fixed by having the encoder scan backwards and the decoder forwards,
  so both observe identical state at every position.
- **`start[-1 - moff]` with `moff` unsigned.** The negation wrapped to +4
  billion. Caught by ASan.
- **`nfilters == HZ_MAX_FILTERS` accepted** on a corrupted header, indexing
  one past the end of the array.

- **every counter started a thousandfold biased.** `HZ_CTR_INIT` was written
  as `2048 << 10`, a half for a 12-bit probability field — but the field is
  22 bits, so a half is `2097152 << 10`. Counters began at p16 = 32 instead
  of 32768 and had to spend real bits unlearning it. The STRONG engine was
  *expanding* input 2.4x when called directly; it only looked fine inside
  the container because the RAW fallback silently swallowed the failure.
  One constant took 64 KiB of text from 165,901 bytes to **26,205**.

Two more that cost ratio rather than correctness:

- **integer truncation froze the counters.** `(target - p) * rate >> 16`
  underflows to zero once the estimate nears an extreme, so a counter stopped
  several hundred units short and put a floor of ~1e-4 bits/bit under the
  output. Rounding the step away from zero took `all-same` from 3,813x to
  **20,971x**.
- **averaging the SSE stages in the probability domain** capped confidence:
  one lagging stage at 0.999 drags a 0.99999 consensus down by an order of
  magnitude in cost. Averaging logits instead was ~9x better on repetitive
  text.
- **the long range matcher used a fixed 2^20-slot table.** At stride 4 a
  64 MiB block inserts 16M positions, so almost every distant repeat was
  evicted before it could be found. Sizing the table to the input and
  keeping two candidates per bucket, plus extending matches backwards over
  bytes already queued as literals, took a near-identical backup set from
  50.7x to **60.3x**.


## Honest limits

- **No compressor shrinks every input.** Counting says so: there are more
  n-bit files than shorter ones, so any lossless codec that shrinks some
  input must expand some other. HYDRA's guarantee is the useful one — a
  block that does not compress is stored raw, so output never exceeds input
  by more than the header.
- The 18,679x and 60x figures above are real and verified, but they are
  properties of *redundant data*, not of the codec. Incompressible input
  (`precompressed.z`) comes back at 1.000x, as it must.
- Level 7–9 encode is under 1 MB/s. That is the price of the model; use
  1–3 when throughput matters.
- Single threaded. Blocks are independent, so this parallelizes cleanly, but
  it is not done here.
